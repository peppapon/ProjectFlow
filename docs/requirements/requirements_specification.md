**Дата:** 07.10.2026

## 1. Введение

Настоящий документ содержит требования к трем основным модулям информационной системы управления проектами ProjectFlow:
- Модуль авторизации (AuthModule)
- Модуль управления задачами (TaskModule)
- Модуль формирования отчётов (ReportModule)

## 2. Модуль авторизации (AuthModule)

### 2.1. Назначение модуля

Модуль обеспечивает аутентификацию и авторизацию пользователей в системе, управление ролями и профилями пользователей.

### 2.2. Функциональные требования

#### FR-AUTH-001: Регистрация пользователя
**Описание:** Система должна позволять регистрировать новых пользователей.

**Входные данные:**
- Имя пользователя (username) - обязательное, уникальное, 3-80 символов
- Email - обязательный, уникальный, валидный формат email
- Пароль - обязательный, минимум 6 символов
- Роль - опциональная (по умолчанию: executor)

**Выходные данные:**
- Информация о созданном пользователе
- Статус операции (успех/ошибка)

**Бизнес-правила:**
- Username и email должны быть уникальными в системе
- Пароль должен хешироваться перед сохранением (bcrypt)

#### FR-AUTH-002: Вход в систему
**Описание:** Система должна позволять пользователям входить в систему с использованием учетных данных.

**Входные данные:**
- Имя пользователя (username)
- Пароль

**Выходные данные:**
- JWT токен доступа
- Информация о пользователе
- Срок действия токена

**Бизнес-правила:**
- Токен действителен 1 час (JWT_ACCESS_TOKEN_EXPIRES)
- Токен содержит claims: user_id, username, role
- Неактивные пользователи не могут войти в систему

#### FR-AUTH-003: Управление профилем
**Описание:** Пользователь должен иметь возможность просматривать и редактировать свой профиль.

**Функции:**
- Просмотр профиля (GET /api/auth/profile)
- Обновление email
- Изменение пароля

#### FR-AUTH-004: Восстановление пароля
**Описание:** Система должна предоставлять механизм восстановления пароля.

**Примечание:** В текущей версии реализован упрощенный механизм. В production-версии требуется интеграция с email-сервисом.

#### FR-AUTH-005: Выход из системы
**Описание:** Пользователь должен иметь возможность выйти из системы.

### 2.3. Роли пользователей

| Роль | Описание | Права доступа |
|------|----------|---------------|
| **administrator** | Администратор системы | Полный доступ ко всем функциям |
| **manager** | Менеджер проектов | Управление проектами, задачами, просмотр всех отчётов |
| **executor** | Исполнитель | Работа с назначенными задачами, просмотр собственных отчётов |

### 2.4. API эндпоинты модуля авторизации

| Метод | Путь | Описание | Аутентификация |
|-------|------|----------|----------------|
| POST | /api/auth/register | Регистрация пользователя | Нет |
| POST | /api/auth/login | Вход в систему | Нет |
| GET | /api/auth/profile | Получение профиля | JWT |
| PUT | /api/auth/profile | Обновление профиля | JWT |
| POST | /api/auth/reset-password | Восстановление пароля | Нет |
| POST | /api/auth/logout | Выход из системы | JWT |

### 2.5. Нефункциональные требования

- **NFR-AUTH-001:** Пароли должны храниться в хешированном виде (bcrypt с cost factor 12)
- **NFR-AUTH-002:** JWT токены должны использовать алгоритм HS256
- **NFR-AUTH-003:** Время жизни токена - 1 час
- **NFR-AUTH-004:** Защита от brute-force атак (rate limiting)
- **NFR-AUTH-005:** Соответствие OWASP Top 10

## 3. Модуль управления задачами (TaskModule)

### 3.1. Назначение модуля

Модуль обеспечивает создание, редактирование, удаление задач, управление их статусами и назначение исполнителей.

### 3.2. Функциональные требования

#### FR-TASK-001: Создание задачи
**Описание:** Система должна позволять создавать новые задачи.

**Входные данные:**
- Заголовок (title) - обязательный, 1-200 символов
- Описание (description) - опциональное, текст
- ID проекта (project_id) - обязательный
- ID исполнителя (assignee_id) - опциональный
- Приоритет (priority) - опциональный (low/medium/high)
- Срок выполнения (due_date) - опциональный

**Выходные данные:**
- Созданная задача со статусом "new"
- ID задачи

#### FR-TASK-002: Просмотр списка задач
**Описание:** Система должна предоставлять список задач с фильтрацией.

**Фильтры:**
- По проекту (project_id)
- По статусу (status)
- По исполнителю (assignee_id)

**Правила доступа:**
- Администраторы видят все задачи
- Менеджеры видят задачи своих проектов
- Исполнители видят только свои задачи

#### FR-TASK-003: Редактирование задачи
**Описание:** Пользователи с соответствующими правами могут редактировать задачи.

**Редактируемые поля:**
- Заголовок
- Описание
- Приоритет
- Срок выполнения

**Права доступа:**
- Администраторы и менеджеры могут редактировать любые задачи
- Исполнители могут редактировать только свои задачи

#### FR-TASK-004: Удаление задачи
**Описание:** Система должна позволять удалять задачи.

**Права доступа:**
- Только администраторы и менеджеры

#### FR-TASK-005: Изменение статуса задачи
**Описание:** Система должна управлять статусами задач с использованием конечного автомата.

**Статусы задач:**
1. **new** (новая) - задача создана, не взята в работу
2. **in_progress** (в работе) - задача выполняется
3. **review** (на проверке) - задача выполнена, ожидает проверки
4. **completed** (завершена) - задача успешно завершена
5. **rejected** (отклонена) - задача отклонена, требует доработки

**Матрица переходов:**

| Текущий статус | Допустимые переходы |
|----------------|---------------------|
| new | in_progress, rejected |
| in_progress | review, rejected |
| review | completed, rejected |
| completed | - (финальный статус) |
| rejected | new, in_progress |

**Бизнес-правила:**
- При переходе в статус "completed" автоматически фиксируется время завершения
- Недопустимые переходы блокируются с возвратом ошибки 400

#### FR-TASK-006: Назначение исполнителя
**Описание:** Менеджеры и администраторы могут назначать исполнителей задач.

**Права доступа:**
- Только администраторы и менеджеры

### 3.3. API эндпоинты модуля задач

| Метод | Путь | Описание | Аутентификация |
|-------|------|----------|----------------|
| POST | /api/tasks | Создание задачи | JWT |
| GET | /api/tasks | Получение списка задач | JWT |
| GET | /api/tasks/{id} | Получение задачи по ID | JWT |
| PUT | /api/tasks/{id} | Обновление задачи | JWT |
| DELETE | /api/tasks/{id} | Удаление задачи | JWT (admin/manager) |
| PATCH | /api/tasks/{id}/status | Изменение статуса | JWT |
| PATCH | /api/tasks/{id}/assign | Назначение исполнителя | JWT (admin/manager) |
| GET | /api/tasks/transitions | Матрица переходов | Нет |

### 3.4. Нефункциональные требования

- **NFR-TASK-001:** Время отклика API не более 200ms для списка до 100 задач
- **NFR-TASK-002:** Поддержка пагинации для больших списков
- **NFR-TASK-003:** Все изменения статусов должны логироваться
- **NFR-TASK-004:** Атомарность операций с использованием транзакций БД

## 4. Модуль формирования отчётов (ReportModule)

### 4.1. Назначение модуля

Модуль обеспечивает формирование аналитических отчётов по задачам и экспорт данных в различных форматах.

### 4.2. Функциональные требования

#### FR-REPORT-001: Отчёт по исполнителю
**Описание:** Формирование отчёта по задачам конкретного исполнителя.

**Входные данные:**
- ID исполнителя (user_id)

**Выходные данные:**
- Информация об исполнителе
- Общее количество задач
- Разбивка по статусам
- Список всех задач

#### FR-REPORT-002: Отчёт по проекту
**Описание:** Формирование отчёта по задачам проекта.

**Входные данные:**
- ID проекта (project_id)

**Выходные данные:**
- Информация о проекте
- Общее количество задач
- Разбивка по статусам
- Разбивка по приоритетам
- Список всех задач проекта

#### FR-REPORT-003: Отчёт за период
**Описание:** Формирование отчёта по задачам за указанный период.

**Входные данные:**
- Дата начала (start_date) - ISO 8601 формат
- Дата окончания (end_date) - ISO 8601 формат

**Выходные данные:**
- Количество созданных задач в периоде
- Количество завершенных задач в периоде
- Список задач

#### FR-REPORT-004: Сводный отчёт
**Описание:** Общая статистика по всей системе.

**Выходные данные:**
- Общее количество задач, проектов, пользователей
- Разбивка задач по статусам
- Разбивка задач по приоритетам

#### FR-REPORT-005: Экспорт в PDF
**Описание:** Экспорт отчётов в формат PDF.

**Технические детали:**
- Библиотека: ReportLab
- Формат страницы: A4
- Таблица с колонками: ID, Title, Status, Priority, Assignee

#### FR-REPORT-006: Экспорт в Excel
**Описание:** Экспорт отчётов в формат Excel (.xlsx).

**Технические детали:**
- Библиотека: openpyxl
- Лист: "Tasks Report"
- Колонки: ID, Title, Status, Priority, Project, Assignee, Created At, Due Date
- Стилизованные заголовки
- Автоматическая ширина колонок

### 4.3. API эндпоинты модуля отчётов

| Метод | Путь | Описание | Аутентификация |
|-------|------|----------|----------------|
| GET | /api/reports/by-user/{user_id} | Отчёт по исполнителю | JWT |
| GET | /api/reports/by-project/{project_id} | Отчёт по проекту | JWT |
| GET | /api/reports/by-period | Отчёт за период | JWT |
| GET | /api/reports/summary | Сводный отчёт | JWT |
| GET | /api/reports/export/pdf | Экспорт в PDF | JWT |
| GET | /api/reports/export/excel | Экспорт в Excel | JWT |

### 4.4. Нефункциональные требования

- **NFR-REPORT-001:** Время генерации отчёта не более 5 секунд для 1000 задач
- **NFR-REPORT-002:** Экспортированные файлы сохраняются в директории reports/
- **NFR-REPORT-003:** Информация об отчётах сохраняется в таблице reports
- **NFR-REPORT-004:** Поддержка кириллицы в экспортируемых документах

## 5. Взаимодействие модулей

### 5.1. Диаграмма взаимодействия

\\\
[AuthModule] --JWT токен--> [TaskModule]
[AuthModule] --JWT токен--> [ReportModule]
[TaskModule] --данные задач--> [ReportModule]
[Все модули] <--> [Database (SQLite/PostgreSQL)]
\\\

### 5.2. Передача данных между модулями

#### AuthModule → TaskModule/ReportModule
- JWT токен в заголовке Authorization: Bearer <token>
- Claims токена: user_id, username, role

#### TaskModule → ReportModule
- Чтение данных из общей БД (таблица tasks)
- Агрегация и формирование статистики

### 5.3. События системы

Модули могут генерировать события для логирования и аудита:

- **auth.user.registered** - новый пользователь зарегистрирован
- **auth.user.login** - пользователь вошел в систему
- **task.created** - создана новая задача
- **task.status.changed** - изменен статус задачи
- **task.assigned** - назначен исполнитель
- **report.generated** - создан отчёт

## 6. База данных

### 6.1. Таблицы

#### users
- id (PK)
- username (UNIQUE)
- email (UNIQUE)
- password_hash
- role (admin/manager/executor)
- created_at
- is_active

#### projects
- id (PK)
- name
- description
- created_at
- updated_at
- is_active

#### tasks
- id (PK)
- title
- description
- status
- priority
- project_id (FK → projects.id)
- creator_id (FK → users.id)
- assignee_id (FK → users.id)
- created_at
- updated_at
- due_date
- completed_at

#### reports
- id (PK)
- name
- report_type
- parameters (JSON)
- generated_by (FK → users.id)
- generated_at
- file_path

### 6.2. Связи

- users.id → tasks.creator_id (1:N)
- users.id → tasks.assignee_id (1:N)
- projects.id → tasks.project_id (1:N)
- users.id → reports.generated_by (1:N)
